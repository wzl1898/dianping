# JMeter 压力测试说明

## 前置条件

1. 启动被测服务：`./start.sh`
2. 确保服务能正常访问：`curl http://localhost:8080/api/shop-type/list`
3. 安装 JMeter 5.x：`sudo apt-get install jmeter` 或从官网下载

## 测试场景

### PT-1: 商户详情查询（缓存命中率测试）
- **目标**：测试缓存对查询性能的提升
- **策略**：100 并发持续 5 分钟，记录缓存命中率
- **对比**：直接查 DB vs 查缓存

### PT-2: 秒杀资格预检（Lua 原子化性能）
- **目标**：测试 Lua 脚本执行性能
- **策略**：模拟 100/500/1000/2000 并发阶梯加压

### PT-3: 秒杀异步下单（RabbitMQ 吞吐）
- **目标**：验证异步下单的吞吐提升
- **策略**：对比同步 vs 异步的 TPS

### PT-4: 限流效果验证
- **目标**：验证滑动窗口限流的准确性
- **策略**：短时间内高频请求，验证限流拦截率

### PT-5: 混合场景（综合业务）
- **目标**：模拟真实用户行为
- **策略**：各接口按比例混合施压

## 测试指标

| 指标 | 说明 | 关注点 |
|------|------|--------|
| TPS | 每秒事务数 | 系统吞吐能力 |
| P50 | 50% 请求的响应时间 | 用户体验中位数 |
| P99 | 99% 请求的响应时间 | 长尾延迟 |
| Error% | 错误率 | 稳定性 |
| CPU/MEM | 资源占用 | 成本效率 |

## 测试流程

### 第一步：登录获取 Token

每个用户先 `/api/user/login` 获取 token，存入变量供后续使用。

### 第二步：预热

用 50 并发预热 30 秒，让缓存生效。

### 第三步：阶梯加压

```
100 并发 → 30s → 记录指标
300 并发 → 30s → 记录指标
500 并发 → 30s → 记录指标
1000 并发 → 30s → 记录指标
2000 并发 → 30s → 记录指标
5000 并发 → 30s → 记录指标（视机器性能）
```

### 第四步：生成报告

```bash
# 生成 HTML 报告
jmeter -g results.jtl -o report/
```

## 秒杀版本对比测试

要对 V1-V8 版本进行对比测试，需要修改 `VoucherOrderServiceImpl` 并重新编译：

| 版本 | 修改点 |
|------|--------|
| V1 | 直接查 DB 扣库存 |
| V2 | 乐观锁 `update ... where stock > 0` |
| V3 | V2 + 唯一键一人一单 |
| V4 | V3 + `synchronized` |
| V5 | V4 + SETNX 分布式锁 |
| V6 | V5 + Redisson |
| V7 | Lua 脚本原子化（当前代码版本） |
| V8 | V7 + RabbitMQ 异步下单（当前代码版本，默认） |

## 预期结果

| 版本 | 预期 QPS | 预期 P99 |
|------|---------|---------|
| V1 | ~200 | ~800ms |
| V4 | ~800 | ~200ms |
| V7 | ~3000 | ~50ms |
| V8 | >3000 | <30ms |
